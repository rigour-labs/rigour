# Rigour 6.8.1

The first release through the new release flow: a release candidate on `next`, the release gates on it, then `latest`.
See [the release checklist](../../RELEASE_CHECKLIST.md#how-a-release-reaches-latest).

## Fixed

- **A clean install prints no deprecation warning.** `@anthropic-ai/sdk` 0.30 pulled in the deprecated
  `node-domexception`; Rigour now uses 0.132, which depends on neither it nor `formdata-node`.
- **The published packages carry no compiled tests.** Every package published its tests too (in `@rigour-labs/core`,
  324 of 996 files), some holding fake credentials as test data. They are left out now (core: 672 files, 2.76 MB
  unpacked instead of 3.66 MB).
- **The Anthropic provider sends no `temperature` to Claude models that reject it.** It sent one on every call, and
  the current Claude families (Fable, Mythos, Opus 5.5, Opus 5, Opus 4.8 and 4.7, Sonnet 5.5 and 5, Haiku 5.5) take no
  sampling parameters, per Anthropic's model guide and OpenRouter's model list. This applied to model review and deep
  analysis with your own Anthropic key; the reviewer that uses your agent's own login was not affected.

## Verified

- The release gates on the candidate: a clean install with no deprecation warning, `init`, `check`,
  `review --base main --json`, `brief --json`, `thread --json`, an upgrade from 6.8.0 with nothing lost, and no
  credential-shaped string in a tarball.
- Anthropic provider: SDK upgraded to 0.132; verified by types, tests, and a live completion through OpenRouter's
  Anthropic-compatible endpoint. The temperature change is verified by tests against the documented model list, not
  by a call to Anthropic's own API.

## Upgrade

`npm install -g @rigour-labs/cli@latest`. Nothing to migrate.
