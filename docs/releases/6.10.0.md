# Rigour 6.10.0

The per-edit check stops flagging TypeScript ESM imports, and findings an older version of the checks reported are no
longer credited to your agent as fixes.

## Fixed

- **The per-edit check no longer flags TypeScript ESM imports.** `rigour hooks check` read `import { b } from './b.js'`
  as a missing file when `b.ts` existed, the way TypeScript's NodeNext and bundler resolution write imports, and with
  `--block` (which `rigour setup` writes) it stopped agents on every edit in such a project. It now resolves imports
  with the same rule as the review: `.js` to `.ts`, `.tsx` or `.d.ts`, `.mjs` to `.mts`, `.cjs` to `.cts`, and a folder
  to its `index`.
- **A finding an older version of the checks reported is never counted as your agent's fix.** When a finding the
  checks no longer report disappeared from a file the agent had edited, it was recorded as a fix: a story in Studio, a
  fixed count for the check, and input for `rigour learn --agent-fixes`. After an upgrade that removes a false finding,
  that credited fixes nobody made. Each open finding now records the version of the checks that reported it. One
  another version reported is checked again by this one: what it still reports stays open, the rest closes as "no
  longer reported", never as a fix. Studio's home page does this on load, and **Check these again** re-checks every
  open finding against the code as it is now.
- **A call written in a string or a comment is not a call.** The security and deprecated-API checks read
  `MSG = "subprocess.call(cmd, shell=True)"` as command injection. Call-shaped patterns now count only from code;
  patterns about a string's contents (secrets, keys, header values) still match inside strings.
- **An import written in a string or a comment is not an import** to the per-edit check: a fixture string, a JSDoc
  line, a `//` comment.
- **A secret under a quoted key is found**: `{"password": "…"}` in JSON, a Python dict or a JS object.
- **`rigour review --diff` of committed work finds what `--base` finds.** HEAD already held the change, so every
  finding on its lines was dropped as the code's own.
- **Class names are read only from class declarations**, not from the end of `dataclass` or the word in a comment,
  so Python files no longer report a naming drift that isn't there.
- **`def run(): return subprocess.run(...)` is not recursion**; a Go method calling itself through its receiver
  still is.
- **An import through an `export * from` barrel counts as a use** for the unused-export check.
- **A handler that only hands the error to a helper** (`return handle(e)`) is no error-handling strategy of its own.

## Changed

- **The reviewer's JSON says what a review spent.** `rigour review --reviewer --json` adds `spent_usd`: every run the
  review made, a failed run, a retry, the orchestrator's fallback and cross-examinations included, and 0 for a verdict
  reused from the cache. `cost_usd` stays as it was, the verdict's judges only, so it under-counts a review with a
  failed run and repeats a cached verdict's earlier cost; read `spent_usd` instead. The terminal's cost line shows the
  spent figure too.
- **The same content is not reviewed again on another commit.** A rebase, an amend, a cherry-pick or the same change on
  another branch reuses the verdict of a full review with the same inputs, once the base under every file it cites is
  checked unchanged.
- **The deep PR review is told what Rigour's checks already found** on the change and drops its own repeat of the same
  kind of issue there; a different problem on the same line is kept and says the line is flagged too.

## Upgrade

`npm install -g @rigour-labs/cli@latest`. Nothing to migrate. Open findings from an earlier version are checked again
the first time Studio's home page loads or the next time your agent edits a file.
