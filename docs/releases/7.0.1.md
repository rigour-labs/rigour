# Rigour 7.0.1

Fixes from the first week with 7.0.0: a team database upgraded to 7.0.0 is usable at once, and a repository or profile
is matched as you meant it when its `origin` uses an SSH host alias or when a broad profile is listed first.

**After upgrading, run `rigour setup`**, so your agent's hooks and MCP server move to this version. If your team shares a
team database, the administrator runs `rigour team init-schema` once more: it grants every member login the tables
7.0.0 added.

## Fixed

- **`rigour team init-schema` grants the member logins it finds** on every team table, the ones a new version adds
  included, and says what it granted and to whom; where it may not grant, it prints the exact `GRANT` statements. After
  an upgrade to 7.0.0, the new tables were left without grants, and a team's first sync stopped until an administrator
  ran the GRANTs `rigour team doctor` printed.
- **A repository whose `origin` uses an SSH host alias is recognized as the team's.** `git@<alias>:org/repo` is compared
  as the host the alias names in your ssh config (read with `ssh -G`); a team pattern with no host (`acme/*`) matches
  the owner and repository on any host; and "not one of the team's repositories" says what was compared.
- **The most specific profile wins.** Re-adding a profile replaces it where it is (`replaced`); matching prefers the
  pattern closest to the repository over the order of the list, so a catch-all never takes a repository a narrower
  profile names; `rigour profile which` names the winning pattern; and a profile's remote pattern matches an `origin`
  on an SSH host alias.

## For contributors

- **Tests that make a git repository no longer race git's own maintenance on cleanup.** Each package's test setup
  turns off git's automatic gc and maintenance, and every git-backed test retries removing its repository.
