# Rigour 7.0.2

Two fixes to what `rigour setup` writes: the push gate leaves a hook that Husky or another tool manages in its hands,
and a team's committed MCP entry keeps its settings when setup moves it to a new version.

**After upgrading, run `rigour setup`**, so your agent's hooks and MCP server move to this version.

**If `rigour` is missing after an upgrade.** After an in-place global upgrade (`npm install -g @rigour-labs/cli@<new>`),
`rigour` may be missing from your `PATH` although npm reported success, or npm may warn `ENOTEMPTY` while it cleans
up. This is npm replacing the package in place, not Rigour. Run the same install again; or uninstall, then install:

```bash
npm uninstall -g @rigour-labs/cli
npm install -g @rigour-labs/cli
```

## Fixed

- **Rigour's push gate no longer replaces a pre-push hook Husky or another tool manages.** Husky 9 points git at
  `.husky/_`, generated stubs that run the tracked `.husky/pre-push`. Setup wrote the gate into the generated folder,
  where it disabled the team's own checks, vanished on the next install, and in a fresh worktree was created untracked.
  Rigour now never writes into a tool-managed hooks folder: a team install adds its line to the tracked script, and a
  personal install prints the line to add. It never replaces another tool's `pre-push`, and `rigour doctor` says
  whether the line is there.
- **`rigour setup --team` keeps the settings on Rigour's MCP entry.** Moving the entry to a new version rewrote it whole,
  dropping its `env` (a working folder, the tool groups a team uses, a telemetry choice) and any other keys. Now only
  the `command` and `args` pin changes, and setup says "your other settings kept".
