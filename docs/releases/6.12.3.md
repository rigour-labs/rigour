# Rigour 6.12.3

Write-only-property follows a value to `Response.json`, and a check that reads FAIL always has a finding that says
why.

## Fixed

- **Write-only-property follows an object literal passed to a serialiser that takes anything.**
  `Response.json({ ok, results })` is followed by the literal's own type, so the fields of a value it carries, even
  through a `Map`, an async function and a same-shape type, are hints, not blocks.
- **A check whose findings sit only outside the change no longer reads FAIL.** In `rigour review --json`, such a
  check reads `PASS` in `checked.checks`, and `checked.outsideChange` gives the count by check, beside
  `checked.preexisting`.
- **The review output says which checks it left out, and why a check fails.** It counts what it left out on two
  lines, each by check: issues the code already had before the change (`review.show_preexisting: true` lists them),
  and issues on lines the change did not touch. A check that fails on a finding about a changed file as a whole says
  so: "About a changed file as a whole: ast-analysis 1, shown with --notes."
