# Rigour 7.0.0

Rigour works while your agent writes, and now shows what it did: Studio names every briefing, every problem it held the
agent for, and counts each problem once. An edit is blocked only for what it did, Rigour's own model spend is capped by
default, and semantic search runs on a library with no open advisories.

**After upgrading, run `rigour setup`.** Your agent's hooks and its MCP server pin the Rigour version they run, and setup
installs the new semantic search library. `rigour doctor` tells you when either is behind.

## What changes for you (breaking)

Most of these shipped in 6.13.0 as a minor release; 7.0.0 marks them as the breaking changes they are.

- **A finding blocks only when Rigour can prove it.** Security patterns other than a real secret's format, prototype
  pollution, a secret-named variable in client code, security-deprecated APIs, side-effect analysis, offset paging and
  unbounded time windows, copied functions, partial fixes and wiring, and behaviour changes found by diff tests are
  notes. Each has a key to make it block again: `gates.security.block`,
  `gates.deprecated_apis.block_security_deprecated`, `gates.side_effect_analysis.block`, `gates.query_patterns.block`,
  `gates.duplicate_functions.block`, `gates.change_sweep.block`; for diff tests, declare an invariant in the pull
  request's description. The table in the [6.13.0 note](6.13.0.md) has each check's before and after.
- **In Claude Code, a real secret is never written.** A credential in a real secret's format (a provider key, a private
  key, a service-account file) denies the tool call before it runs; anything the scan only suspects is a warning the
  agent sees. Until 6.13.0 the scan before a tool call checked nothing in Claude Code.
- **`rigour setup` briefs the agent and gives it Rigour's MCP server by default.** `--no-brief` leaves the briefing out;
  `rigour uninstall` removes both.
- **Rigour's hook commands are rewritten.** Each is a plain command, pinned to the exact Rigour version, that runs in
  any shell. Run `rigour setup` after upgrading so your agent's hooks and MCP server move with it.
- **`rigour_check` and `rigour_get_fix_packet` judge the agent's change the way the stop hook does:** what must be fixed
  first, then notes, and nothing from code the change did not touch. `rigour_check` with `scope: "repo"` audits the
  whole repository.
- **Rigour's model spend is capped by default.** With the reviewer on, a repository has caps of 40 runs and $10 a day,
  and $2 per review, checked before every judge, retry, cross-examination and follow-up. A review that reaches one stops
  there, keeps what it had, and says which cap. The deep review's cloud model (`rigour check --deep` with a key) counts
  toward the same caps and does not start past them. Raise them in `rigour.yml`: `review.reviewer.max_runs_per_day`,
  `max_usd_per_day`, `max_usd_per_review`. A person may set lower caps for their own runs, never higher.
- **Semantic search moved to `@huggingface/transformers`.** Run `rigour setup` to install it; existing indexes keep
  working. Details below.
- **The edit hook blocks only on what the edit did.** A finding the file already had at its last commit is a note, and
  file size blocks only when the edit takes the file over `max_file_lines`.

## While your agent writes

- **An edit is blocked only for what it did to the file.** A file already over `max_file_lines` blocked
  every edit to it. Now file size blocks only an edit that takes a file over the limit; growing one already over is a
  note, and shrinking one is nothing. The edit hook's other checks work the same way: what the file already had at its
  last commit is a note, never a block.
- **An agent that starts in a subfolder is briefed too.** The briefing read files relative to where the session
  started, so from a subfolder a folder rule never applied; it now reads from the repository's top, with the repository's
  own switch.
- **A secret in a plain assignment is flagged.** `password = "…"`, `DB_PASSWORD=…` and the like, in code,
  JSON, YAML, TOML or a .env file, are a note in review and a warning the agent sees before writing them, unless the value
  is a placeholder, a reference or a test value. It never blocks, `security.block` included, until its false-positive
  rate is measured; `gates.security.secret_assignments: false` turns it off.
- **A secret in a camelCase assignment is flagged too:** `dbPassword = "…"`, `apiToken: "…"`, as Go, JS
  and TS write them, and never a name inside a longer word (`passwordless`, `tokenizer`). Same status: a note and a
  warning, never a block.
- **Claude Code's credential scan reads what the tool will write.** It scanned the JSON envelope of the
  tool call, where every quote is escaped, so a quoted assignment like `password = "…"` could never match. It now scans
  the tool call's own text.
- **A push says when a cap skips the model review.** The agent is told the cap and its key instead of "it runs in
  the background", and notes on a push that goes ahead now reach the agent at all: they were written where Claude Code
  shows no one.

## What Studio shows

- **Studio shows what the agent was told before it wrote.** Each briefing appears in Activity with the
  rules and lessons it gave and the files they were for.
- **Studio names what the stop held the agent for:** the file, the check and what was wrong, as it does for an edit.
- **Studio counts each problem once.** A problem stopped at an edit and again before done is one problem, counted
  where it was first caught; the week counts what is still open as well as what was fixed, and every view agrees.

## Learning from reviews

- **A review lesson with no file is never shown as a team standard** unless a person scoped it to the repository;
  it reads "(no file)" and reaches a change only by its words.
- **Two writers of the review lessons store never overwrite each other.** Studio, a CLI run and the outcome loop
  can change lessons at the same time: short changes take a lock, long runs merge with the store as it is when they
  write, and nothing either side added is lost.
- **The team database can hold people's decisions on review lessons,** append-only: `rigour team init-schema`
  adds them with no change for earlier clients, `rigour team doctor` says whether they are there, and it needs PostgreSQL
  13 or later.
- **An sme's or owner's decisions on review lessons reach the team database:** accepting, rejecting, scoping or
  rewording a lesson, sent once each by the team sync from the team's repositories only, with the approved wording and
  hashes, never review text or logins. A member's decisions stay on their machine. Every decision, in the CLI or Studio,
  is now refused when no git email is set in the checkout, so none is recorded as nobody.
- **Teammates' decisions on review lessons reach every clone.** The team sync receives them for the team's
  repositories and keeps them under the Rigour home, never in the committed lessons file, so names never reach git
  history. The brief, review, Studio and `learn-reviews --list` all see them. For each question the latest person
  decision wins: a teammate's from when the team database received it, yours from when it arrived or, until it does,
  yours holds.
- **The brief says which teammate approved or rejected a lesson**, by the display name the team database holds,
  never a login or an email: "learned in PR #7, approved by Jane D. (team)".
- **Studio shows teammates' decisions on each review lesson** by name and date, and says when a later team
  decision settled a lesson against yours, and why yours is yours only.
- **Promote or drop a fresh review candidate in Studio.** Every candidate learned from review comments has
  **Promote** and **Drop** on its card in **How it learns**, recorded under your git email as `rigour learn-reviews
  --promote` does; before, Studio offered them only once evidence had moved a candidate.
- **A team sets up its own team database alone:** TEAM_DATABASE.md has a start-to-finish guide, and
  `rigour team sync --dry-run` shows how many of your decisions on review lessons the first sync brings in, and which
  decisions in the clone stay because someone else made them.
- **`gates.deep.review_lessons: all` is documented for what it serves:** review points as their reviewers wrote
  them, which no person has confirmed. The default stays verified lessons only, so a new team sees few lessons in its
  briefings until a person confirms some.

## Security and dependencies

- **The MCP server's dependencies are on their patched versions:** `@modelcontextprotocol/sdk` 1.32.1 and
  the web stack it brings (hono, @hono/node-server, proxy-addr, path-to-regexp, fast-uri). Nothing to change on your side.
- **Semantic search moved to `@huggingface/transformers` 4.3.1.** The library `rigour setup` installed
  brought a critical (protobufjs) and a high (sharp) advisory to every machine. Run `rigour setup` to install the new one;
  it removes the old copy, and existing indexes keep working (the same model gives the same vectors: cosine at least
  0.992 on our sample, on Linux and macOS). Setup skips the ONNX runtime's GPU download and keeps only your platform's
  runtime: about 250 MB on Linux and 280 MB on macOS, about what the old one took.
- **The CLI's interactive list uses current prompts:** `rigour check --interactive` no longer pulls in
  `inquirer` 9 and the vulnerable `tmp` it brought. It looks and works the same.
- **The test runner and Studio's build tool are on their patched versions:** vitest 4 (no more tinypool)
  and vite 6. Nothing to change on your side.
- **The rest of the dev and build tooling is on patched versions:** handlebars, js-yaml, postcss, nanoid,
  browserslist, undici 7 and others, through the lockfile only. Nothing to change on your side.

## Fixed

- **Two tests that could time out on a slow runner are fast and offline.**

## For contributors

- **Test runs no longer pick up compiled files.** Vitest 4 stopped leaving `dist/` out, so a built package
  ran compiled copies of its tests too (twice the count, and a stale one could fail or pass unseen). Each package's
  config now runs `src/**/*.test.ts` only.
- **Two PRs that each add a `rigour.yml` key pass alone and fail together on the config reference's count:**
  regenerate `docs/CONFIG_REFERENCE.md` after merging one, before the next.
