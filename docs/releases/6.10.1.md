# Rigour 6.10.1

Studio says what Rigour actually did, a repeated finding reads once, and two checks stop flagging code that is right.

## Fixed

- **Studio never says an edit was blocked when it wasn't.** Without `--block`, the per-edit hook reports findings and
  the agent carries on, but Activity said "Stopped an edit" and counted it as blocked. The hook now records whether it
  blocked. Activity says "Reported on an edit to …" unless it did, and counts those as "edits reported on". A record
  written before this version has no such flag, so it reads as reported.
- **A repeated finding reads once on Studio's home page.** Open findings are grouped by check and message. Twenty-five
  copies of one problem show as one line, "25 × Import … not found, in 12 files", which opens to the findings, newest
  first. The heading counts findings and their kinds: "61 findings need you, of 5 kinds".
- **Studio's header names the repository, never its path.** It showed the checkout's absolute path, which put your
  username into every screenshot, and package.json's name and version. It now shows the origin remote's repository
  name (else the folder name) and the branch, and Studio's info endpoint no longer sends the path at all. The browser
  tab says "Rigour Studio".
- **A read-only Studio tab says how to get edit rights, in one line.** Open the link `rigour studio` printed in your
  terminal: that link gives the tab edit rights. The note can be hidden for the tab.
- **The learning page says how lessons reach an agent.** An agent gets them when it asks for a brief (`rigour_brief`,
  or `rigour brief`). In Claude Code, `rigour hooks init --brief` hands them over by itself, at a session's first
  prompt and on each file's first edit. The page used to say agents were always told before they wrote.
- **An optional member read back from stored JSON is a hint, not a block.** "Optional member every host supplies"
  blocked a field that every writer sets but that older stored data lacks, such as a stamp added to records read with
  `JSON.parse` or `readJson`. Making the field required would make the type lie about that data. When values of the
  type are read back from JSON as that type, the finding is now a hint (`rigour review --notes`) that names the read.
- **The context-drift check covers Scala.** `.scala` files are scanned, and `case class`, `implicit class` and
  `private[pkg] class` count as class declarations.
