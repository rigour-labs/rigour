# Rigour 6.12.0

A person can make a lesson a standard for the whole repository, so a point your reviewers keep raising reaches the
agent and the reviewer on every change, not only on the file where it was first made. Nothing changes until a
person decides.

## New

- **Team standards: a person decides how far a lesson reaches.** A lesson learned from a review is tied to the file
  it was made on, and a file it was never about got nothing. Now a person can widen it:
  - `rigour learn-reviews --scope <id> --to repo` makes it a team standard, served with every change, whatever its
    files or words. `--to folder` serves it with every change in its folder; `--to file` takes it back. `--why`
    records the reason.
  - In Studio, each review lesson's card shows how far it reaches, with **Make team standard**, **Folder only** and
    **This file only**.
  - Each decision is recorded with your git email. Studio refuses one without a git email set.
- **A person decides every one.** Rigour never widens a lesson on its own. A scope says how far a lesson reaches,
  never whether it is right, so the lesson's state does not change. Scoping a candidate records the decision; it
  reaches agents once the candidate becomes a lesson (a person accepts it or corrects it, or the same point recurs across reviews), or at once
  in a repository that serves candidates too (`gates.deep.review_lessons: all`). `rigour learn-reviews --scope` says
  so when you scope a candidate.
- **Where a team standard reaches:** the briefing at the start of a session, the briefing on a file's first edit,
  and the reviewer's (and the deep review's) team knowledge. Up to ten are served, the most-raised first. The
  briefing on a file's first edit keeps its limit of three, so there the three most-raised come after the file's
  own lessons.

Lessons that no one has scoped behave exactly as in 6.11.
