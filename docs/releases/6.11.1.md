# Rigour 6.11.1

Style-drift stops flagging code that is fine, a check that can't compare says so, lessons keep what the reviewer
asked for, and a RIGOUR_HOME ending in `.rigour` no longer doubles the state folder.

## Fixed

- **Style-drift no longer depends on earlier runs.** In a git checkout it compares changed and new files with the
  code committed at the base, read fresh on every run, and keeps no baseline file. A `.rigour/style-baseline.json`
  left by an earlier version is ignored. A check on a clean tree gives the same result however many checks ran
  before it on a dirty one. Outside git, nothing changes.
- **Style-drift reads names as people write them.** A one-word lowercase name (`run`, `data`) or a dunder
  (`__init__`) counts as neither camelCase nor snake_case, and a private name is read without its leading
  underscores (`_load_rows` is snake_case). A snake_case project with short or private names is no longer told it
  is camelCase or "other".
- **Style-drift compares variables with variables.** Module constants (`MAX_ROWS`, `_RETRY_DELAYS`) no longer count
  toward a project's variable casing.
- **A check that can't compare now reports SKIP with its reason instead of PASS.** Style-drift and logic-drift
  with no main branch to compare with show `SKIP`, the reason is under the gate grid, and `--json` carries it in
  `skips`.
- **A lesson keeps what the reviewer asked for.** It keeps the instruction after the diagnosis, and identifiers as
  written (`RESTOCK_CHUNK`, not `RESTOCKCHUNK`). Reading the reviews again updates an undecided lesson in place. A
  lesson a person decided keeps its wording, and the corrected one waits for them: `rigour learn-reviews --list`
  shows it, and `--use-wording <id>` or **Use this wording** in Studio takes it.
- **A RIGOUR_HOME ending in `.rigour` is the state folder itself.** State was written one level deeper
  (`.rigour/.rigour`). Where an earlier version already wrote state there, it stays in use and nothing is moved;
  `rigour doctor` says how to move it.
