# Rigour 6.11.0

A verified review lesson can become a free check that runs without a model, the reviewer can try a cheaper model
first, and opt-in telemetry says a little more. **Every new feature in this release is off until you turn it on.**

## Off by default, and how to turn each on

| Feature | Default | Turn it on |
| --- | --- | --- |
| Lessons compiled into checks | Nothing runs until a person approves a check | `rigour learn-reviews --compile`, then `--approve-check <id>` (or **Approve** in Studio). Findings are notes; `gates.compiled_lessons.block: true` makes them block |
| Cheaper model first (reviewer) | Off; experimental | `review.reviewer.tiers.cheap: { <judge>: <model> }` in `rigour.yml` (team only) |
| More telemetry fields | Sent only if you said yes to telemetry | `rigour telemetry on` (`rigour telemetry status` says which) |
| Studio's model-reviewer numbers | Shown only when there are numbers | the outcome record (`learning.outcomes.mode: on`, or `RIGOUR_OUTCOMES=on`) with the model reviewer running |

## New

- **A verified review lesson can be compiled into a check** ([REVIEWER.md](https://github.com/rigour-labs/rigour/blob/main/docs/REVIEWER.md), "Lessons compiled into checks").
  - **Eligible lessons:** verified by a person, a correction or recurrence; naming its file and a symbol.
  - **Two templates, no model:**
    - forbid: "never use `a`", or "use `b` instead of `a`";
    - require: "always `a` with `b`".
  - **A person decides.** `rigour learn-reviews --compile` proposes checks. `--approve-check <id>` runs one, recorded with your git email. `--withdraw-check <id>` takes it back. Studio's learning page has the same **Approve** and **Take back**. The checks live in `.rigour/compiled-checks.json`, committed and reviewed like code.
  - **Its history first.** Each proposal shows how the check would have fired on the main branch's last 100 commits to its files: on pull requests where a review found the lesson repeating, and on every other change. A percentage appears only from ten.
  - **Where it runs:** on changed lines, as a note unless `gates.compiled_lessons.block` is on.
  - **Out of the prompt.** Where an approved check ran on a change, its lesson leaves the model reviewer's and the deep review's prompt, and the prompt names the check instead. Taking the check back returns the lesson. A check whose lesson stops qualifying is suspended.
- **Cheaper model first, for the reviewer: experimental, and its saving is unmeasured.**
  - **When the cheap model runs:** for a change with no risk signal (no human reviews to check, no items carried from the last verdict, no migration, no security finding, no declared goal, no risky changed function, no required floor, and a change the router could score). Anything else runs the team's model.
  - **One escalation:** a cheap answer that isn't a valid verdict is retried once on the team's model. What blocks is unchanged.
  - **A safety stop, not a promise:** it turns itself off if, over its recent reviews, it cost more than one judge would have.
  - **Not yet known:** how much it saves, or what the cheap model misses. Don't make it a default until that is measured on your own reviews.
- **Opt-in telemetry says a little more** ([TELEMETRY.md](https://github.com/rigour-labs/rigour/blob/main/TELEMETRY.md) lists every field). Sent only with your consent, the off switches unchanged:
  - which agent ran Rigour (`claude-code`, `cursor`, `cline`, `windsurf`, `codex`, `other` or `none`);
  - how long ago you were first asked, in buckets;
  - per check, how many findings were fixed, dismissed or reached a pull request;
  - once a day after `rigour review`, what the repository's learning loop did. That covers which switches are on and who set them, the outcome counts, and lesson decisions.

  Counts and fixed values only. Never a repository, file, finding or lesson text, and never a dollar amount.
- **Studio's learning page shows the model reviewer's numbers** beside the free checks, from the outcome record `rigour outcomes` prints:
  - how many findings at first review came from the model, a percentage only from ten pull requests;
  - what it cost, a median only from ten.

## Fixed

- **Studio's "How Rigour works" says what's true.**
  - Which agents are checked as they edit: Claude Code, Cursor, Cline and Windsurf. Any agent is checked at push.
  - Rigour stops the agent only on problems it can prove.
  - Fixes become lessons only with learning on.
